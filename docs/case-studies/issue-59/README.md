## CI-CD-BEST-PRACTICES principles

| #   | Principle                                   | Where it is applied                                                                                                                                 |
| --- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Run checks only on relevant changes         | `detect-code-changes.mjs`; path filters on `workflows.yml` and `links.yml`.                                                                         |
| 2   | File size limits                            | `check-file-size.mjs` (code, workflows, Markdown ≤ 1500 lines).                                                                                     |
| 3   | Automated formatting                        | Prettier in CI and in lint-staged.                                                                                                                  |
| 4   | Static analysis                             | ESLint with `--max-warnings 0`, CodeQL, ShellCheck, actionlint, zizmor.                                                                             |
| 5   | Fast-fail job ordering                      | Tests need lint; releases need lint, tests and the preflight.                                                                                       |
| 6   | Changeset-based versioning                  | `validate-changeset.mjs`, required only when package code changed; changesets merged before versioning.                                             |
| 7   | Validate the merge result                   | `simulate-fresh-merge.sh` tests the PR merged into the latest `main`.                                                                               |
| 8   | Pre-commit hooks                            | husky + lint-staged, installed by `install-git-hooks.mjs`; the hook has a shebang and LF endings.                                                   |
| 9   | Release automation                          | Release recovery, push classification, 25-minute visibility window, non-retryable publish errors, registry smoke test.                              |
| 10  | Concurrency control                         | Job-level groups; `main` never cancels a release; one `main-writer` group for pushes to `main`.                                                     |
| 11  | Secrets detection                           | secretlint over the whole tree before install.                                                                                                      |
| 12  | Documentation validation                    | lychee link check, `check-required-docs.mjs`.                                                                                                       |
| 13  | Container images per architecture           | Not applicable: the package ships no images.                                                                                                        |
| 14  | Lint the workflows                          | actionlint, zizmor, the status-gate coverage check and `test/ci-workflow-policy.test.js`.                                                           |
| 15  | Audit the dependency tree                   | `npm audit` and `bun audit`, dependency review behind the graph preflight.                                                                          |
| 16  | Prove you can publish before you build      | `check-npm-publishing.mjs` before versioning.                                                                                                       |
| 17  | Tell a broken pipeline from a changed world | Human-action states warn on PRs and fail on `main` with the action to take; permanent refusals are not retried; every dispatch input has a default. |
