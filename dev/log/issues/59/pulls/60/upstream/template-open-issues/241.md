# 241 npm run lint exits 0 with warnings, and on main hides all six existing warnings, so CI never enforces what the pre-commit hook (--max-warnings 0) rejects

## Summary

`npm run lint` (`scripts/lint.mjs`) exits 0 whenever there are no **errors**, whatever the warning count. Two consequences:

1. **On pull requests,** warnings on changed lines are printed, and the job still passes. The pre-commit hook runs `eslint --fix --max-warnings 0`, so a contributor who skips the hook (`--no-verify`, a web edit, a bot commit) lands exactly what the hook would have rejected, and CI stays green. That's a false negative.
2. **On pushes to `main`,** there are no "changed lines" to filter on, so every warning is hidden behind a summary line:

```
$ node scripts/lint.mjs; echo exit=$?
6 warning(s) on unchanged lines were not reported. Run LINT_ALL_WARNINGS=1 npm run lint to see them.
exit=0
$ LINT_ALL_WARNINGS=1 node scripts/lint.mjs; echo exit=$?
...
✖ 6 problems (0 errors, 6 warnings)
exit=0
```

(Template at 0a62b80.) All six are `local/no-changelog-comments`, in comments that cite PR or issue numbers:

- `experiments/test-failure-detection.mjs` lines 3 and 39
- `scripts/js-paths.mjs` line 3
- `scripts/update-preview-images.mjs` line 2
- `tests/package-info.test.js` line 1
- `tests/tag-prefix.test.js` line 1

Because none of these fail CI, the rule that exists to stop history comments only ever produces noise.

## Suggested fix (applied and verified in konard/voice-simulator#4, commit 9e6ca0c)

1. Fail on any **reported** error or warning, so CI matches the pre-commit hook:

```js
/**
 * Exit code for the reported results: any error or any reported warning
 * fails. The pre-commit hook runs ESLint with --max-warnings 0, so CI rejects
 * what a skipped hook would have rejected.
 */
export function lintExitCode(reported) {
  return reported.some((result) => result.errorCount + result.warningCount > 0)
    ? 1
    : 0;
}
...
process.exit(lintExitCode(reported));
```

Pull requests are still held only to warnings on the lines they change.

2. Report every warning on `main`, where there is no diff to scope by:

```yaml
      - name: Run ESLint
        # Pull requests are held to warnings on the lines they change; main
        # must stay free of warnings everywhere.
        env:
          LINT_ALL_WARNINGS: ${{ github.event_name != 'pull_request' && '1' || '0' }}
        run: npm run lint
```

3. Rewrite the six comments to describe current behaviour.

Tests: `lintExitCode` passes only when nothing is reported, fails on a reported warning, and fails on an error. A workflow test asserts that the `Run ESLint` step sets `LINT_ALL_WARNINGS` for non-pull-request events.
