# 238 eslint ^9 is deprecated on every install, and eslint.config.js imports @eslint/js without declaring it, so the ESLint 10 bump breaks

## Summary

`package.json` pins `"eslint": "^9.38.0"`. Every published ESLint 9 release (the line ends at 9.39.5) is now deprecated:

```
$ npm view eslint@9.39.5 deprecated
This version is no longer supported. Please see https://eslint.org/version-support for other options.
```

Any install that resolves from the registry prints the warning. The template's own `main` run shows it in the "Regenerate Preview Images" job ("Install browser automation dependencies": `npm install --no-save --package-lock=false ... browser-commander playwright` at the repository root, which resolves every root devDependency from the registry), run 38049674017, https://github.com/link-foundation/js-ai-driven-development-pipeline-template/actions/runs/38049674017:

```
npm warn deprecated eslint@9.39.5: This version is no longer supported. Please see https://eslint.org/version-support for other options.
```

(`npm ci` from the lockfile does not fetch packuments, so it stays quiet; the version is just as unsupported there.) Beyond the log noise, this is a supply-chain signal: the line no longer gets security fixes.

Upgrading has a second, hidden problem. `eslint.config.js` starts with

```js
import js from '@eslint/js';
```

but `@eslint/js` is **not declared** in `package.json`. It only resolves today because ESLint 9 depends on it and npm hoists it. ESLint 10 no longer depends on `@eslint/js`, so after a plain bump to `eslint@10`, a clean install can no longer resolve that import (`npm view eslint@9.39.5 dependencies` lists `@eslint/js`; `npm view eslint@10.12.0 dependencies` does not).

## Suggested fix (applied and verified in konard/voice-simulator#4, commit 9f7d4f5)

1. `"eslint": "^10.12.0"` and declare `"@eslint/js": "^10.0.1"` in `devDependencies`. Pick a version older than 24 hours if Deno's minimum dependency age is enforced, because Deno refuses newer packages.
2. Fix what ESLint 10's `recommended` set newly reports, rather than disabling the rules:
   - `no-useless-assignment`: e.g. `let hooksPath = '';` immediately overwritten in a `try`.
   - `preserve-caught-error`: `throw new Error(\`Failed to read ${filePath}: ${error.message}\`)` inside `catch`, which should pass `{ cause: error }`.
   Occurrences we found in the shared scripts: `scripts/install-git-hooks.mjs`, `scripts/merge-changesets.mjs`, `scripts/package-info.mjs`, `scripts/smoke-test-package.mjs` and the `experiments/test-format-*.mjs` files.
3. Add a regression test so an undeclared config import can't come back:

```js
it('imports only packages that package.json declares', () => {
  // ESLint 9 hoisted @eslint/js, so an undeclared import still resolved;
  // ESLint 10 no longer depends on it.
  const config = readFileSync('eslint.config.js', 'utf8');
  const pkg = JSON.parse(readFileSync('package.json', 'utf8'));
  const declared = { ...pkg.dependencies, ...pkg.devDependencies };
  const imported = [...config.matchAll(/from '([^.][^']*)'/g)].map(([, spec]) =>
    spec.split('/').slice(0, spec.startsWith('@') ? 2 : 1).join('/')
  );
  expect(imported).toContain('@eslint/js');
  for (const name of imported) {
    expect(`${name} ${typeof declared[name]}`).toBe(`${name} string`);
  }
});
```
