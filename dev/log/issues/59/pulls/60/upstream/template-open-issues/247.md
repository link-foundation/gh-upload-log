# 247 Skipped matrix jobs are listed as 'Build Docker Image (${{ matrix.platform }})': names with matrix expressions are never expanded for skipped jobs

## Summary

When a matrix job is skipped, the Actions UI and the jobs API list it under its unexpanded name. For example, template `main` run [38049673812](https://github.com/link-foundation/js-ai-driven-development-pipeline-template/actions/runs/38049673812) shows:

```
Build Docker Image (${{ matrix.platform }})   skipped
```

GitHub evaluates `jobs.<id>.if` before it applies `strategy.matrix` ([docs](https://docs.github.com/en/actions/using-jobs/using-conditions-to-control-job-execution)). A skipped job never gets matrix values, so the expression in its name is never evaluated.

Two jobs in `release.yml` can be skipped and put `matrix.*` in their name:

- `docker-publish-build`: `Build Docker Image (${{ matrix.platform }})`, skipped whenever Docker publishing is off.
- `test`: `Test (${{ matrix.runtime }} on ${{ matrix.os }})`, skipped when its `needs` skip.

## Suggested fix (applied in konard/voice-simulator#8)

Use a static `name:` such as `Build Docker Image` or `Test`. GitHub then appends the matrix values to expanded jobs, for example "Test (node, ubuntu-24.04)", with the matrix keys ordered runtime first. A skipped job shows just its name.

A policy test fails if any job with `if:` or `needs:` puts `${{ matrix.` in its name.
