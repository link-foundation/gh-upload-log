# 242 format-release-notes.mjs drops everything after '---' and every later changeset entry, and links only the first PR

## Summary

`scripts/format-release-notes.mjs` rewrites the GitHub release body that Changesets produced, and in doing so it **silently drops content**:

- Everything after a `---` inside an entry is cut, and so is every **later entry**.
- Only the first entry's commit is looked up, so only **one PR** is linked even when the release contains several changesets.
- Literal `\n` sequences and quotes are "cleaned", so code spans like `` `\n` `` and quoted text are altered.
- The nested-list structure is flattened (the leading `- <hash>: ` is stripped, and indentation is changed).

The script passes, the release is published, and nothing reports the loss. That's a false negative in the release pipeline.

## Reproduction (template at 0a62b80)

[`experiments/issue-3-release-notes-e2e.sh`](https://github.com/konard/voice-simulator/blob/issue-3-a4cd49414cf6/experiments/issue-3-release-notes-e2e.sh) runs the real script against a stub `gh`, using this release body:

```md
### Patch Changes

- 68f606a: First change.

  Second paragraph.

  - nested

  ---

  After a rule, with `\n` and a "quote"
- def5678: Second entry
```

Run from a template checkout (`cd template && bash path/to/issue-3-release-notes-e2e.sh`), the body it PATCHes onto the release is:

```md
First change.

Second paragraph.

- nested

**Related Pull Request:** #41

---

[![npm version](...)](...)
```

"After a rule…" and the whole `def5678` entry (PR #42) are gone.

## Suggested fix (applied and verified in konard/voice-simulator#4, commit 9643526)

Publish the change sections the way Changesets wrote them, and look up every commit:

- `buildReleaseDescription(body)` in `scripts/format-release-notes-helpers.mjs` returns `{ description, commitHashes }`, or `null` when there's no `### Major|Minor|Patch Changes` section.
  - With a single section, the description is that section's content verbatim. With several, it keeps their `### … Changes` headings.
  - Only line endings (CRLF to LF) and trailing whitespace are normalized.
  - `commitHashes` are the unique `- <hash>:` entries, at any nesting.
- `format-release-notes.mjs` loops over every hash (falling back to the passed `--commit-sha`) and collects unique PR numbers. It then writes `**Related Pull Request:** #N` or `**Related Pull Requests:** #a, #b`.
- The `\n`/quote/`---` "cleanup" is removed.

With the fix, the same reproduction publishes the body unchanged, followed by `**Related Pull Requests:** #41, #42`. `tests/release-notes-description.test.js` covers these cases:
- multi-paragraph, nested-list, rule, escape and quote content
- entries without a hash
- multiple sections with CRLF and duplicate hashes
- bodies without change sections
