# 236 format-release-notes.mjs flattens multi-paragraph changesets and nested lists, drops text after ---

## Summary

`scripts/format-release-notes.mjs` changes the Markdown structure of the changelog section it formats. A changeset with several paragraphs or a nested list is written by changesets as one list item whose continuation lines are indented by two spaces. The cleanup step trims every line (`.map((line) => line.trim())`, [line 154](https://github.com/link-foundation/js-ai-driven-development-pipeline-template/blob/d8eefdefd4a275db244c002d68f02237ede0aa9f/scripts/format-release-notes.mjs#L145-L156)), so those lines leave the list item. The same step also:

1. drops the first item's `- <hash>:` marker, because the section regex `/### (Major|Minor|Patch) Changes\s*\n\s*-\s+(?:([a-f0-9]+):\s+)?(.+?)$/s` captures the text after it;
2. cuts everything after the first `---` anywhere in the notes (`.replace(/---.*$/s, '')`), including a horizontal rule or a `--flag---` inside a changeset;
3. turns a literal `\n` (for example inside a code span) into a line break (`.replace(/\\n/g, '\n')`);
4. strips quotes the notes start or end with (`.replace(/(['"])+$/g, '')`), so a changeset ending in `"quoted"` loses its closing quote;
5. looks up the PR of the first commit hash only.

These cleanups date from when release bodies were passed through shell arguments. The body is now sent as JSON on stdin (`--input -`), so the `\n` and quote workarounds only damage correct text.

## Impact

Found while fixing link-assistant/hive-mind#3445: the [v2.37.1 release](https://github.com/link-assistant/hive-mind/releases/tag/v2.37.1) of hive-mind rendered one bullet followed by 18 loose paragraphs. An audit of all 893 hive-mind releases found 302 with lost indentation, 21 more with missing text and 37 never formatted. Example in this template's own downstream: [link-foundation/start v0.13.0](https://github.com/link-foundation/start/releases/tag/v0.13.0) lost the `- 7763ae1:` bullet and the indentation of its nested list (compare with its CHANGELOG.md section).

## Reproduction

```js
// node repro.mjs: the cleanup step of scripts/format-release-notes.mjs (lines 145-156)
const body = `### Patch Changes

- 68f606a: First change.

  Second change of the same changeset.

  - nested bullet
  - another nested bullet

  ---

  Text after a rule, and a literal \`\\n\` in code. Ends with a "quote"`;

const changesPattern = /### (Major|Minor|Patch) Changes\s*\n\s*-\s+(?:([a-f0-9]+):\s+)?(.+?)$/s;
const [, , , rawDescription] = body.match(changesPattern);
const cleanDescription = rawDescription
  .replace(/\\n/g, '\n')
  .replace(/^(\\['"])+/g, '')
  .replace(/(['"])+$/g, '')
  .replace(/^(['"])+/g, '')
  .replace(/📦.*$/s, '')
  .replace(/---.*$/s, '')
  .trim()
  .split('\n')
  .map((line) => line.trim())
  .join('\n')
  .replace(/\n{3,}/g, '\n\n');
console.log(cleanDescription);
```

Actual output: the bullet and hash are gone, the second paragraph and the nested list are no longer inside the item, and everything from `---` on is lost:

```
First change.

Second change of the same changeset.

- nested bullet
- another nested bullet
```

Expected: the section exactly as changesets wrote it (only trailing whitespace removed).

## Workaround

Fix a published release by rewriting its body from the CHANGELOG.md section, for example `gh api repos/OWNER/REPO/releases/ID -X PATCH --input body.json`. hive-mind ships [`scripts/repair-release-notes.mjs`](https://github.com/link-assistant/hive-mind/pull/3446) for this; it rebuilds every affected release (dry run by default).

## Suggested fix

Keep the structure and strip only what the formatter itself adds. This is the change made in link-assistant/hive-mind#3446 (`scripts/format-release-notes.lib.mjs`):

```js
const CHANGE_SECTION = /^### (Major|Minor|Patch) Changes[ \t]*$/gm;

const normalizeMarkdown = (text) =>
  String(text || '')
    .replace(/\r\n?/g, '\n')
    .split('\n')
    .map((line) => line.replace(/[ \t]+$/, '')) // trailing whitespace only
    .join('\n')
    .replace(/\n{3,}/g, '\n\n')
    .replace(/^\n+/, '')
    .replace(/\s+$/, '');

function buildReleaseDescription(body) {
  const text = String(body || '').replace(/\r\n?/g, '\n');
  const headings = [...text.matchAll(CHANGE_SECTION)];
  const sections = headings
    .map((match, i) => ({
      type: match[1],
      content: normalizeMarkdown(text.slice(match.index + match[0].length, headings[i + 1]?.index ?? text.length)),
    }))
    .filter((section) => section.content);
  const commitHashes = [...text.matchAll(/^[ \t]*[-*][ \t]+([a-f0-9]{7,40}):/gm)].map((m) => m[1]);
  if (sections.length === 0) return { description: normalizeMarkdown(text), commitHashes };
  if (sections.length === 1) return { description: sections[0].content, commitHashes };
  return {
    description: sections.map((s) => `### ${s.type} Changes\n\n${s.content}`).join('\n\n'),
    commitHashes,
  };
}
```

Also:

- Drop the `\n` and quote replacements; the body is sent as JSON on stdin.
- Look up the PRs of every hash in `commitHashes`, not only the first.
- In `create-github-release.mjs`, match the version heading as a whole line (`^## 1.2.3[ \t]*$`) so `1.2.3` never reads the `1.2.30` section.

Tests that cover these cases are in [`tests/issue-3445-release-notes-formatting.test.mjs`](https://github.com/link-assistant/hive-mind/pull/3446).
