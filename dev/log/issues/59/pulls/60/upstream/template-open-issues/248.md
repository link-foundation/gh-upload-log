# 248 release.yml bump_type has no default (HTTP 422); links.yml --cache is never persisted and its report artifact is never uploaded; prettier || true hides errors

Found while comparing link-foundation/start's CI/CD with this template (https://github.com/link-foundation/start/issues/234). Checked against template HEAD `0a62b80` (2026-10-10). Each item below caused a false result in start, and each is fixed there in PR https://github.com/link-foundation/start/pull/235. The fixes are linked for reuse.

### 1. `bump_type` has no `default:`, so dispatching through the API gets HTTP 422

`.github/workflows/release.yml:22-29`:

```yaml
      bump_type:
        description: 'Manual release type'
        required: true
        type: choice
        options: [patch, minor, major]
```

- **Reproduce:** `gh workflow run release.yml -f release_mode=instant`, which gets HTTP 422 because `bump_type` is required and has no default. `CI-CD-BEST-PRACTICES.md` §17 makes the same point: "the dispatch API answers HTTP 422 without it".
- **Fix:** add `default: patch`. A test that every `required: true` input has a `default:` keeps it fixed. See start's `js/test/ci-workflow-invariants.js`, test "gives every required dispatch input a default" (commit https://github.com/link-foundation/start/commit/9f07fed).

### 2. `links.yml` passes `--cache` but never persists `.lycheecache`; the failure message points at an artifact that is never uploaded

- `links.yml:74-75` passes `--cache --max-cache-age 1d`, but nothing restores or saves `.lycheecache`. Every run therefore starts cold, and `--max-cache-age` never applies. The comment at line 46, "Typical run: <1min with lychee cache", describes a cache that never exists.
- `links.yml:137` prints `Report location: lychee/out.md (available as a workflow artifact if configured).` No `upload-artifact` step exists, so a failed run leaves nothing to inspect.
- **Reproduce:** run the workflow twice. The second run's lychee log shows no cache hits, and the run page has no artifacts.
- **Fix:** start's `links.yml` (commit https://github.com/link-foundation/start/commit/a4d3784):

```yaml
      - name: Restore lychee cache
        uses: actions/cache@v5
        with:
          path: .lycheecache
          key: cache-lychee-${{ github.sha }}
          restore-keys: cache-lychee-
      # ...
      - name: Upload lychee report
        if: ${{ !cancelled() && steps.lychee.outputs.exit_code != 0 }}
        uses: actions/upload-artifact@v7
        with:
          name: lychee-report
          path: lychee/
          retention-days: 14
```

  These have regression tests: "persists the lychee cache it asks for" and "uploads the report the failure message points at" in start's `js/test/links-workflow.mjs`.

### 3. `Format changeset with Prettier` swallows its own failure

`release.yml:994`: `npx prettier --write ".changeset/*.md" || true`.

- A Prettier error (a bad glob, a missing binary, a parse error) is hidden. The PR is then opened with an unformatted changeset, and the error only shows up later, as a red format check on that PR.
- **Fix:** drop `|| true`. If an empty glob is the concern, check for files first.

### 4. Related, already fine here: lint warnings and npm propagation

This template already does both of these correctly. Start had copied older versions:

- `eslint --max-warnings 0`. Start's `eslint .` exited 0 on warnings.
- A long post-publish registry wait, with conflict-as-landed handling (`publish-retry.mjs`). Start waited only 60s.

Mentioned only so the other templates can be checked for the same gaps.
